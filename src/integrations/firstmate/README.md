# firstmate

Reads configured Firstmate homes and turns their tasks into cards. Read-only: it never writes a home, never patches Firstmate and never looks at its backends (Paseo, Herdr, tmux).

- `status.ts`: parses `state/<task>.status` lines and folds keyed decisions the way Firstmate does (needs-decision and blocked open a key, resolved and captain-held close it, a ship or scout terminal line closes all).
- `home.ts`: reads `state/<task>.meta`, the status log, `data/backlog.md` and `data/<task>/brief.md` into one observation per task: backlog title, repo tag, pull request (only from the meta's `pr=` field), the canonical worktree from the meta's `worktree=` field and the Paseo terminal it was launched in from `paseo_terminal_id=`, latest activity, open decisions and notes. The notes are each needs-decision and resolved line (decisions) and done line (summary) with its text, and the brief's `## Captain's intent` section (context).
- `sync.ts`: folds a home into the board through the single writer (one card per task, parented to the home's card, decisions and a latest failed: or blocked: line as blocking attention, a task in the backlog's Done section as outcome done, or a closed failure when its last line was failed:, without that line's attention; that outcome is a source observation re-derived on every sync, cleared when the task leaves Done, so undo and `outcome` refuse it and a manual move pins the card instead), records an open task's worktree as the card's folder (a closed task, or one whose records are gone, gives it up, since pools reuse worktrees) and its latest Paseo terminal whenever it changes (a joined session's fuller terminal facts stay while it does not), so the hook session running there, or a new one after a clear or a respawn, joins the task card (sync replaces only the attention it derives and keeps that session's `hook:` entries), appends each task's notes once as `card.noted` events, and watches `state/` and `data/` with `fs.watch`, reconciling on start and after a watcher error.
- `reply.ts`: sends a reply or decision answer through the home's own `bin/fm-send.sh <task> [--resolve-key <key>] <text>` with `FM_HOME` set and reads its exit status as delivered, delivery_unknown or failed; `pnyx-axi reply` (`src/cli/reply.ts`) records the receipts. A setting change from the Agent tab is a typed command on the same route, followed for Claude Code's model and effort by `fm-send.sh <task> --key Enter` to answer its confirmation. A secondmate task (whose input fm-send marks as a message) and a remote task (`remote_host=` in its meta, inbox only) take no commands; `typingReason` in `home.ts` says why.
- `cli.ts`: the `pnyx-axi firstmate sync|watch` commands, and `watchHomes`, which `pnyx-axi serve --home` also runs.
