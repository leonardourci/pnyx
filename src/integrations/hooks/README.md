# hooks

Claude Code and Codex hooks as a source of cards.

- `setup/hooks/pnyx-hook.sh` is the hook itself, a POSIX shell script copied to `$PNYX_HOME/hooks/` by `pnyx-axi setup hooks`. It prints nothing, exits 0 every time and never waits on the network, a browser or a model. It wraps the harness payload in one JSON line (`{v, id, at, harness, event, payload}`) and writes it to the default board's server socket `$PNYX_HOME/boards/default/server.sock` (the server handles each line as soon as its newline arrives and replies nothing, so the hook never relies on nc half-closing) or, when no server is listening, straight to that board's spool. Tool hooks pass on only `gh pr create`, `gh pr merge` (or their `gh-axi` forms) and the known deploy commands listed in `observe.ts`, which counts them only in command position: at the start of the command or after `&&`, `||`, `;` or `|`.
- `observe.ts` turns a spooled payload into card observations, keyed `<harness>:<session id>` and `<harness>:<session id>/<agent id>` for subagents, with the parent, working folder and transcript path. Activity comes from the event (started, working, idle, ended). Each observation offers an auto title: the first line of a prompt, else the working folder's name. SessionEnd (SubagentStop for a subagent) records the outcome `ended`, owned by hooks; a later SessionStart, prompt or tool event clears it. Hooks never change an outcome another source or a person recorded. A created pull request's URL becomes a link with no state, a hint to refresh it rather than proof.
- `settings.ts` reads a session's settings from hook payloads and transcript records: model, effort, permission mode and fast mode under the same names for both harnesses, plus settings only one harness has (Claude Code's context window, Codex's approval policy, sandbox, collaboration mode and reasoning summary, and each one's client and version). `observe.ts` puts a payload's settings on the card; `harvest.ts` adds what the transcript gained and records only a change.
- `notes.ts` reads the notes a harness already wrote into a session transcript: Claude Code's compaction summaries, older summary records and session titles, each AskUserQuestion question with the user's answer, and Codex's readable compaction summaries (a remote compaction is encrypted and yields none), plus the thread name Codex keeps for the session in its home's `session_index.jsonl`. A session title note also becomes the card's title unless one was set. Nothing is generated.
- `harvest.ts` appends those notes to the session's card as `card.noted` events, each with an id derived from its card and source record, so a re-read appends nothing twice. It runs after a Stop, SubagentStop or SessionEnd event is ingested, and on `pnyx-axi harvest`. `harvest.json` in the board's folder remembers how far each transcript was read; deleting it costs one re-read, never a duplicate.
- `install.ts` merges Pnyx's entries into the user-level `settings.json` (Claude Code, `CLAUDE_CONFIG_DIR`) or `hooks.json` (Codex, `CODEX_HOME`), keeping every other hook, and takes them out again with `--remove`. No session-start board summary is installed.
