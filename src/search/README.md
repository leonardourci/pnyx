# search

Full-text history search: `pnyx-axi search "<words>"`, `search status` and `search rebuild`.

- `search.db` in the board's folder is a derived index, not a store. It is deletable like `snapshot.json` and rebuilt from `events.jsonl` and the transcripts the hooks recorded; nothing reads it as board state.
- `index.ts` is its only writer. Each search first folds in what the log and the transcripts gained since the `cursors` table (the event seq and byte offset; per transcript its device and inode and byte offset). A replaced or shortened transcript is read again. A `meta` table holds the schema and chunker versions; on mismatch the file is deleted and rebuilt. Building a new index first harvests every card's transcript (`pnyx-axi harvest`, transcripts only), so compaction summaries are notes before they are indexed.
- `docs` holds one row per chunk with its card, kind (`event`, `note` or `transcript`), source, event seq or transcript line offset, part and time; `docs_fts` is an FTS5 external-content table over it. `card_fts` holds one contentless row per card (its title and link titles, its notes, and all its other chunks), rebuilt when the card gains or loses chunks or is renamed, so every word of a query can match anywhere on a card. Cards are ranked by BM25 on it, the title and link titles weighing half and notes double, and shown with their best-matching chunks; `--card` and `--kind` match single chunks instead, a note chunk also ranking double.
- Both FTS5 tables use the `porter unicode61 remove_diacritics 2` tokenizer: words match by stem, with case and accents folded. `terms` holds every distinct indexed word (folded, unstemmed) and `terms_tri` its trigrams. When a query finds nothing, each word is retried with the indexed words nearest it by trigram similarity, or containing it, and the hits are marked `fuzzy`.
- `synonyms.ts` is the versioned synonym map: a query word or phrase in a group matches the whole group. Add a group there and bump its version.
- `text.ts` decides what is indexed: the text events carry, including harvested notes, and typed user messages and assistant text from Claude Code and Codex transcripts (not tool calls or output, thinking, injected text or a compaction summary, which is a note), with secret-shaped strings redacted, cut by a deterministic, versioned chunker.

Semantic search, off until `pnyx-axi search setup --semantic`:

- `settings.ts` reads and writes `$PNYX_HOME/settings.json` (`search.semantic`, `search.rerank`, `search.model`), shared by every board; `pnyx-axi settings` and the web board's settings change it. Turning on a setting whose model or runtime is not installed is refused.
- `models.ts` pins each GGUF by URL, size and SHA-256 and downloads it into `$PNYX_HOME/models/`; it also holds each embedder's golden vectors and the reranker's golden scores for fixed probe texts.
- `runtime.ts` pins node-llama-cpp and sqlite-vec, which are not pnyx-axi dependencies: `search setup --semantic` installs them with npm into `$PNYX_HOME/runtime/`, and the worker and the vector scan load them from there. Without that folder, semantic search reports the runtime as not installed and search stays full-text.
- `backend.ts` runs the models through node-llama-cpp on its GPU backend (Metal, CUDA, Vulkan) or CPU, never building from source, and refuses a model whose probes drift from the golden values. `PNYX_SEMANTIC_STUB=1` swaps in hash vectors and a word-overlap reranker so tests never load a model.
- `worker.ts` is the process that loads models for searches and indexing (`search setup` also loads them once, in its own process, for their golden check): one per Pnyx home, spawned on demand by `semantic.ts` at low priority (utility QoS on macOS), listening on a socket named after a hash of the home in a `pnyx-<uid>` folder in the temp folder that only this user can use (on Windows a named pipe whose name also hashes the write token), with its output in `$PNYX_HOME/semantic.log`. It answers query embeddings, reranking and status, embeds each queued board's missing chunks newest first in small transactions, closing the index while it embeds, skips a chunk the model cannot embed, and exits after a minute idle or once semantic search is turned off, answering the requests it holds first.
- `vectors.ts` keeps one vector per distinct chunk text in the `vectors` table (keyed by `docs.content_hash`, so repeated text, a re-read transcript or a log reset is not re-embedded; deleting or rebuilding `search.db` re-embeds everything), with `embed.key` (model, file, backend) and `embed.probes` in `meta`; a different key or drifted probe drops them all. Queries scan them exactly with sqlite-vec's cosine distance, best chunk per card, under the same workspace and kind filters.
- `semantic.ts` fuses the full-text and vector card lists by reciprocal rank fusion, reranks the top 20 when the reranker is on (marking `weak` results and printing `no strong match`), and falls back to full-text results, saying why, when the worker cannot answer. `--card` and `--lexical` stay full-text only.
- `pnpm test:semantic` checks the real models end to end (it downloads them, or links them from `PNYX_GOLDEN_MODELS`).
